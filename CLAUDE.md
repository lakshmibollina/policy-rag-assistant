# Working on this project

This is a portfolio project. I'm learning, and I need to explain every part of it in job interviews.

## How to work with me

- Work one build step at a time (see the Progress list in README.md). Don't jump ahead.
- Before writing code, explain in plain words what we're about to build and why.
- Keep code simple and readable, with short comments. Prefer a small number of clear files over clever abstractions.
- After each change, tell me how to run it and what I should see.
- When there's a design choice (chunk size, model, library), list the options, recommend one, and explain the trade-off.
- Never put API keys in code. Read them from `.env` with python-dotenv.

## At the end of every step

1. Update README.md: tick the step in Progress, update the Status line, add any new results.
2. Add an entry to docs/build-log.md: what we did, what we decided and why, problems hit, and any numbers.
3. Give me a 2-3 sentence "interview answer" for the step.
4. Suggest a commit message.
